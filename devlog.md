### [ДЕНЬ 30] :: Финал войны с инструментами
Потестить OpenCode, видимо, руки не дойдут. Зачем оно мне? В моем приложении уже есть редактор кода и файлов, просмотр баз данных, управление терминалами, подключение к LLM. У меня теперь хоть 50 терминалов со статусами, логами и кнопками Play/Kill — больше не надо записывать команды в блокнотики. Я сам себе написал OpenCode, пока собирался его тестировать. Зачем мне чужие доки теперь курить?.

### [ДЕНЬ 28] :: Браузер как syscall
Дневники вайбкодинга: почему бы не добавить браузер с вкладками прямо в Mission Control?. Это не просто для серфинга, а чтобы боты могли работать 24/7 без лимитов клауда на время исполнения. Пока заюзал для тестов сервер со 144 ядрами.

### [ДЕНЬ 27] :: YOLO-mode и права доступа
Самые важные команды CLI для работы без тормозов:
`codex --yolo`
`claude --dangerously-skip-permissions`.
У меня все агенты работают в режиме полного беспредела: ноль вопросов, ноль согласований, полные права на всё. Границы — только мои правила в файлах.

### [ДЕНЬ 26] :: Мечта о железном терабайте
Мечтаю о домашней машинке:
- 4×80GB GPUs (320GB VRAM) + 1TB ECC RAM
- gpt-oss-120b (stable 128K context)
- qwen2.5-1m-* (1M+ context).
Локальные LLM — нереальная круть. Окно контекста в космос и ноль лимитов, чтобы сутки работало нон-стоп. Клауд-агент всегда будет экономить ресурсы поставщика, он работает не на тебя.

### [ДЕНЬ 24] :: Иерархия диагностики
Дневники вайбкодинга: дружба роботов.
1. Process Supervisor — источник сигналов (status, last_line).
2. Ollama (oss20b) — первый уровень: классифицирует инцидент и решает, звать ли Codex.
3. Codex — эскалация: запускается в нужной сессии с уже структурированным контекстом.

### [ДЕНЬ 22] :: Протокол войны с Гитом
Главная проблема — постоянная война с Git. Пошла уже 9-я версия протокола. Агенты требуют всё более строгих правил:
- Стадия 1: Косячат агенты.
- Стадия 2: Дали протокол и скиллы.
- Стадия 3: Агенты косячат, права отобрали, оверлорды пушат.
- Стадия 5: Скилл требует соблюдать протокол.
Забрал у ботов ключи, сделал скилл `git-publish`. Теперь только Pull Request, никакого мусора в контексте.

### [ДЕНЬ 19] :: Intent-first Insight
Сделал персонализацию по мотивам ресерча. Атас, как изменились ответы: Тебе не нужен большой MVP. Тебе нужен «Proof that intent-first execution works locally». Нужно строить среду, где человек и машина разделяют память, границы и цели. Это и есть зачаток новой операционной модели.

### [ДЕНЬ 14] :: Автономная аренда
У меня боты прямо сами себе сейчас сервера арендуют под задачу. Скилл следит за балансом, пополняет криптой, заливает образы и гасит сервера, когда не нужны. Доступ к инфраструктуре, которая стоила бы 7000$ в месяц, за 40$ на задачу.

### [ДЕНЬ 05] :: Лень как фильтр
Склепаю-ка по-быстренькому тулзу для записи всей шляпы в БД из любого места терминала... 5 часов спустя: новая спека. Понял, что локальная модель может 8 часов искать инфу в интернете и ей норм, а ChatGPT отвалится через 15 минут.

### [ДЕНЬ 01] :: Сессия вместо памяти
Важный инсайт: у LLM нет функции «очистить память». Есть сессия. Контроль контекста — это то, что отличает инженера от казуального пользователя. В CLI ты годмод: полный контроль в их родной среде обитания.
